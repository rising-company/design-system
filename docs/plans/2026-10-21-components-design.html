The missing building blocks

2026-10-21 · status: accepted · item 4 of the design review

The system specifies cards, lists, buttons, fields and the shells, but not the pieces every product reaches for next. Each product invents its own icons, dialogs, toasts, tables and toggles, and they drift apart. This doc proposes all seven, in the order they unblock each other, so each can ship as one small PR.

Decided, details at the end: (1) the icon set is Lucide with squared ends, (2) the system stays CSS and markup only. No React package. Everything else follows the rules the system already has.

Order of work

Icons come first because four of the others need one: a close button, a check, a toast's state, and a sort arrow. The form controls come next because they are small and self-contained. The two overlay components come last, because they depend on the focus and motion rules being settled.

Rules every component inherits

  • Faces: labels and options use the text face (IBM Plex Sans). Readouts such as column headers and counts use mono. Titles use Rajdhani.
  • Sizes: only the seven --type-* steps. A control is never smaller than 14px.
  • Targets: 44px minimum on coarse pointers, using the same @media (pointer: coarse) rule buttons already have.
  • Colour: tokens only. Mint appears as a fill (--accent) for "on" or "selected", and as --accent-ink for focus and text.
  • States: rest, hover, press (instant), focus-visible (the existing 1px --accent-ink ring), disabled, and an error state where one applies.
  • Motion: Quick for colour, Base spring for anything that moves, Slow for a modal and its scrim. Reduced motion keeps the opacity change and drops the movement.
  • Accessibility: native elements first (<dialog>, <input type=checkbox>, <table>), so focus, keyboard and screen readers work without extra code.
  • Themes and contrast: each component is checked in Mission, Daylight, auto, Increase Contrast and forced colours.

1 · Icons

Problem: the user-menu chevron is drawn with CSS borders, the auth points use a typed +, and the back link is a typed ←. Nothing lines up with the text beside it, and products pick whatever is nearby.

Proposal: adopt Lucide (ISC licence, about 1,500 icons, with matching npm packages for React and plain SVG). Restyle it to the brand:

  • Squared stroke ends. Use stroke-linecap: square; stroke-linejoin: miter. Lucide's default round ends read as friendly and generic; square ends match Rajdhani's corners and the HUD brackets. This is the one change that makes the set ours.
  • Stroke 1.5px at every size, set with absoluteStrokeWidth, so a 16px icon isn't thinner than a 24px one.
  • Three sizes paired with type: 16px beside 14px text, 20px beside 16px text, 24px for icon-only buttons and the nav.
  • currentColor only. An icon takes the colour of the text it sits with, and never carries meaning by colour alone.
.icon { width: 1.25em; height: 1.25em; flex: none; vertical-align: -0.25em;
        stroke: currentColor; stroke-width: 1.5; fill: none;
        stroke-linecap: square; stroke-linejoin: miter; }
.icon-sm { width: 16px; height: 16px; }   .icon-lg { width: 24px; height: 24px; }
.btn-icon { width: 44px; height: 44px; padding: 0; }   /* icon-only: needs aria-label */
  • Delivery: products use lucide-react plus the .icon class. Static pages use a small branding/icons.svg sprite with only the icons the system uses, referenced with <use href>.
  • Accessibility: a decorative icon gets aria-hidden="true". An icon-only button needs an aria-label and a tooltip.
  • First users: the user-menu chevron, the back link, the + points, the card arrow, and the status of a toast.

2 · Checkbox & radio

Use native inputs, styled with accent-color rather than redrawn. They stay accessible, work in forced colours, and need no script.

.check { display: flex; align-items: center; gap: 12px; min-height: 44px; font-size: var(--type-body); color: var(--text-body); }
.check input { width: 20px; height: 20px; margin: 0; accent-color: var(--accent-ink); }
  • The label is a sentence in the text face, and the whole row is clickable through <label>.
  • A group sits in a <fieldset> whose <legend> uses .field-label. Help and error text follow the field rules.
  • Radio or checkbox: radios for one choice among 2–5. Beyond five, use a select. A checkbox is a choice that takes effect when the form is submitted.

3 · Switch

A switch is a setting that takes effect immediately. If nothing happens until Save, use a checkbox instead.

<button class="switch" role="switch" aria-checked="false"><span class="switch-thumb"></span></button>

.switch { width: 40px; height: 24px; border-radius: 12px; background: var(--bg-inset); border: 1px solid var(--border-hover); }
.switch[aria-checked="true"] { background: var(--accent); border-color: var(--accent); }
.switch-thumb { width: 18px; height: 18px; border-radius: 50%; background: var(--text-heading); /* Base spring on translate */ }
.switch[aria-checked="true"] .switch-thumb { background: var(--accent-on); transform: translateX(16px); }
  • The 40×24 visual sits inside a 44px row, and the label to its left is clickable too.
  • "On" is shown by the thumb's position as well as the fill, so it doesn't rely on colour alone. In forced colours the thumb keeps ButtonText.

4 · Segmented control

A segmented control switches between 2–4 views of the same content, such as Day / Week / Month or the showcase's Mission / Daylight / Auto. It is not navigation: if the URL should change, use the nav or tabs.

  • Markup is a radio group (role="radiogroup" with native radios, or buttons with aria-pressed), and arrow keys move the selection.
  • Labels are the text face at 14px/500 in --text-muted. The selected segment is --accent-wash with --accent-ink text. The segments sit in one 1px --border frame with hairline dividers.
  • The showcase theme switch becomes the reference build.

5 · Table

A table is for comparing values across rows. If each row is a thing you open, use .list (from PR #6).

  • Header: mono 12px uppercase --text-dim on --bg-inset, sticky inside its scroll container. A sortable header is a button with a 16px icon and aria-sort.
  • Cells: 14px text face. Numbers are right-aligned with font-variant-numeric: tabular-nums, which Plex supports, so columns line up. IDs and hashes are mono.
  • Rows: 44px minimum, hairline --border-subtle between rows, no zebra stripes. Hover uses --bg-surface-hover only when the row does something.
  • Phones: the table scrolls sideways inside its own frame, with the 24px edge fade from the phone nav. The page itself never scrolls sideways. If a phone user needs only two columns, the product shows a list instead.
  • Empty and loading: the existing empty state goes inside the frame. While loading, skeleton rows breathe on opacity, the only other loop the motion rules allow.

6 · Toast

A toast confirms something the person just did, and offers to undo it. It never carries anything they must act on: that belongs in the page, or in a dialog.

  • Position: bottom-right on desktop and bottom-centre on phones, above the footer. One toast at a time; a new one replaces the old one.
  • Anatomy: a status icon, one sentence in the text face at 14px, and an optional single action button ("Undo") in .btn-ghost .btn-sm. It sits on a surface with a 1px border. No title.
  • Timing: success and info stay 5s. The timer pauses while the pointer is over the toast or it has focus. An error stays until dismissed.
  • Accessibility: success and info use role="status" (polite); errors use role="alert". Focus never moves to a toast.
  • Motion: the toast enters with the Base spring, rising 8px, and exits at 0.6× fade only. Reduced motion fades only.

7 · Dialog & sheet

A dialog asks one question that blocks the task, such as "Delete this huddle?" or a short form. A long flow gets its own page instead.

stateDiagram-v2
  [*] --> Closed
  Closed --> Open: trigger · showModal()
  Open --> Closed: Escape · scrim click · Cancel
  Open --> Working: primary action
  Working --> Closed: success → toast
  Working --> Open: error shown inline
  • Built on native <dialog> with showModal(). The browser handles the focus trap, Escape and the inert background. Focus goes to the first field, or to Cancel for a destructive dialog. On close it returns to the trigger.
  • Anatomy: a .card-title question, one or two sentences of body, then actions on the right with the primary last. A destructive dialog uses btn-danger, and its button names the action ("Delete huddle"), never just "OK". 480px maximum width on a surface with radius 6. The close button is an icon with an aria-label.
  • Scrim: ::backdrop in color-mix(in srgb, var(--bg-base) 70%, transparent), fading at Quick.
  • Sheet (≤ 640px): the same markup becomes a bottom sheet: full width, top corners radius 12, a 44px grab area, and the safe-area inset at the bottom. It slides up with the Slow spring. Desktop and phone share one component.
  • Busy state: the primary button shows the existing aria-busy state. An error appears inside the dialog, never as a toast behind it.

Decisions

1. Icon set: Lucide, with squared ends. It's the largest well-maintained set, and the squared ends give it our shape. Phosphor, Tabler and a custom set were considered and set aside.

2. CSS and markup only. The system ships classes, tokens and markup recipes in llms.txt; each product wires behaviour in its own framework. There is no shared React package. A product on React uses lucide-react itself, and the .icon class squares the ends, because CSS properties override SVG presentation attributes.
